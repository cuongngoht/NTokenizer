## Synthesis (inference, not evidence)
- Best path to Markdown that keeps headings, lists and tables for viwiki: take Enterprise HTML (article_body.html) from the Snapshot API with a free account, then run HTML→Markdown with GFM tables (claims 5, 6, 10). The HF `wikimedia/wikipedia` parquet is the quickest clean plain text but uses an old snapshot (20231101). Whether its mwparserfromhell `strip_code` output keeps lists or tables was not verified. WikiExtractor JSON is fine for plain text only. CirrusSearch is currently unreliable (claim 7). Structured Contents table parsing is not validated for vi (claim 9).
- Mixing: there is no primary-source ratio for encyclopedic vs news text. Precedent is to upsample Wikipedia about 2–3 epochs at a few % of the mix (claims 13, 14). For a small Vietnamese model where Wikipedia and news are the whole corpus, a reasonable hypothesis is to start around 30–50% Wikipedia, upsampled ≤3 epochs, and tune on held-out loss per domain (claim 15). This is untested.
